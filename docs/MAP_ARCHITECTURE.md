# V5 地图架构

## Phase 0 基线审计

本地旧分支起点是 `19f921e`。远端 `main` 经只读核对已到 `d55555d`，包含全员专属 3D 资产、真人二次出拳排序及更新的角色规则。最终实现以该远端提交为父级完成集成。旧分支用于早期基线取样，正式对比使用 `d55555d` 的原始代码。工作区已有六张未跟踪历史截图。

- 规则层创建每人一间初始房间。Socket.IO 快照携带 `roomIds`、玩家当前位置和延迟事件。本轮以这些字段为准。移动接受任一合法初始房间，真人与 AI 共用引擎。
- `Game` 同时持有战斗演出 Hook 和 3D 封装。Three.js 创建 Canvas，DOM 投影负责标签，现行主分支的角色注册表已有 11 个内建角色的独立程序化模型，旧分支只有五条悟的独立模型及共用人形。当前重复探测在有扩展时会主动释放上下文，场景卸载没有显式释放主上下文。2D 路径保留。
- `engine.ts` 写入攻击宣告、伤害、回复、移动、淘汰及技能日志。延迟爆炸先发房间事件，随后按结算瞬时成员产出影响事件，最后检查胜负。房间广播保留递增 seq。
- `BattleEventQueue` 按 seq 去重，按行动簇调度。旧 3D 入口从 React 叠加层差分取事件，快照同步提前呈现了位置、HP、死亡和胜利姿态。3D 镜头和弹层各自决定终局呈现时机。
- 现有石台、主题图腾、步行动画、角色注册表、拖拽、缩放、2D 回退与上下文恢复策略可复用。旧地图把当前本机房间固定在前缘，换房会重排场景，旧石径没有随之重建。旧房间泊位在六个后取模。
- 基线命令为 `npm test`、`npx tsc -p client/tsconfig.json --noEmit`、`npm run build`。本机受限沙箱阻挡测试回环连接，放开该测试命令的回环权限后 Socket.IO 基线通过。浏览器基线与后续比较见验收文档。

## Phase 1 · 空间与交互

`createRuinsMap(roomIds)` 返回按房间 ID 索引的悬浮遗迹定义。每个锚点提供中心、朝向、边界半径、踏面高度、入口、标签锚点、镜头焦点与泊位。少量房间分布在单环，十一间以上使用双环。地图拓扑只在权威房间集合变化时重建，当前本机房间、角色进出和淘汰都不会移动石台。石径根据布局生成几何，也随拓扑更新。

每个房间按稳定 PID 顺序为新成员分配空泊位，留在房间的成员保留原泊位。重连后若场景仍挂载也沿用已占泊位，整页刷新则由恢复快照确定起始分配。已倒地角色在尸体淡出期间保留自身泊位，离房或实体移除时释放。由测试检查 2–20 间石台边界和 20 个同房泊位。地图只用房间 ID 派发点击；单设备多人按当前本机行动者显示技能及合法目标，提交继续使用既有 Socket.IO 接口和服务端校验。

## Phase 2 · 场景与资源

场景以既有六棱台和图腾为锚，加入悬浮地层、石桥、中央仪式台及远景碎岩。围栏和桥面砖使用实例化绘制。Canvas 上的角色与 HTML 名牌分别负责空间归属与文字交互。密集对局的确认栏提供权威房间和候选角色下拉入口。

`Battle3D` 在有效的 3D 挂载中尝试创建一个 WebGL2 渲染器，由真实上下文检测适配器。2D 期间没有 3D Canvas。软件渲染像素比维持 1，硬件默认最高 1.55，精简特效时使用 1。上下文恢复等待沿用原有会话降级策略。卸载撤销 RAF、指针与可见性监听、观察器和恢复定时器，释放场景所有权内的特效、实例缓冲、几何、材质及上下文。缩小拓扑、领域消失与危险标记移除都立即释放对应子树资源。重开同一房间沿用画布，清空上一局的角色和临时表现。

## Phase 3 · 已确认事件与镜头

```tex
Socket.IO 快照与递增日志
  ├─ 权威画面信息、行动资格及提交
  └─ BattleEventQueue
       ├─ React 叠加状态 → 既有 2D 牌桌
       └─ 按播报节拍订阅 → 地图展示投影 → 角色 / 房间 / CameraDirector


- 队列按 seq 去重，支持同包重复、长度触顶的滚动日志窗及阶段分隔。范围事件在首个伤害前增加以真实结构化房间为依据的预警节拍，各目标和多段顺序沿用原日志。大伊万使用爆炸日志给房间上色，命中和淘汰只读取后续服务端事件。阶段日志断开旧行动和新行动之间的队列簇。
- 地图投影暂缓揭示尚有确认事件的房间、HP、存活和待爆。移动使用日志起点和终点，HP 读取日志 `hpBefore` / `hpAfter`，淘汰节拍启动后才呈现倒地。权威快照独立驱动规则、行动坞和服务端提交。过载压缩、跳过、后台暂停或补发中的缺失事件以最新快照收敛。重连使用兼容的 `catchUp` 标记推进游标，实时包继续演出。
- 镜头导演同一时间持有一条指令。全局、房间、行动者、目标、区域、重大事件、胜利和平局由各自预设定义取景和寿命。重复指令合并、高优先级保护当前节拍、拖拽或缩放交还操控权。视角按钮回到全局并恢复自动镜头资格，画面菜单可以持续停用自动镜头。系统减少动态效果时采用全局静态机位。
- 同批终局快照和尾随日志在浏览器首次绘制前纳入终局门控。队列走完且尾帧驻留后才触发胜者姿态和机位，3D 给终局机位约 760ms 的展示窗口后进入弹层。玩家可直接结算，异常积压在 19s 后清队列并收敛到权威结果。不在角色组件上运行全局演出定时器。
