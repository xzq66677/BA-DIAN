# 入口视觉 · 地图适配层（BAStage）指南

## 这个适配层解决什么

入口原型 `prototypes/v5-entrance.html` 曾把地图相关的一切写死在主体里：台面高度、主台/侧台/栈桥几何、八个锚点坐标、六组机位、遗物与接触阴影、雾与三点布光。地图一改就得改原型主体，容易带崩交互。

现在这些全部收敛到 `prototypes/stage-adapter.js`。**原型主体不再出现任何地图数值**，只通过稳定接口取用。换地图只做一件事：`define()` 一个新适配器，或访问 `?stage=<id>` 切换。

## 接口契约

一个适配器是一个对象，字段如下（必填除标注外）：

```js
BAStage.define({
  id: 'my-map',                 // 唯一标识，?stage=my-map 用它切换
  label: '我的地图',            // 展示名
  floorY: 1.22,                 // 台面高度；角色落地 y = floorY + FOOT_LIFT
  coreRadius: 2.65,             // 主台半径（供 build 内几何用）
  roomRadius: 2.7,              // 侧台半径

  anchors: {                    // 八个落点，全部 {x,z}；hero 是缺省回退
    hero:         {x:0,   z:0},
    seat0:        {x:4.9, z:4.4},   // 大厅席位 1
    seat1:        {x:-4.9,z:4.4},   // 大厅席位 2
    seat2:        {x:0,   z:-7.2},  // 空席位
    selectFocus:  {x:-0.95,z:0.28}, // 选角焦点位
    selectOther:  {x:0.9,  z:-0.55},// 选角对照位
    battlePlayer: {x:-1.35,z:0.4},  // 战场玩家侧
    battleRival:  {x:1.35, z:0.4},  // 战场对手侧
  },

  views: {                      // 机位 {pos:[x,y,z], look:[x,y,z], fov}
    introHigh: {...}, lobby: {...}, battle: {...},   // 静态机位
    menu:   function(mobile, floorY){ return {...}; },       // 动态：按横竖屏
    select: function(mobile, floorY, h, w){ return {...}; },  // 动态：h=身高系数 w=武器宽度系数
  },

  build: function(scene, THREE, spec, floorY){
    // 构建：雾、灯光、主台、侧台、栈桥、遗物、散景、接触阴影
    // 返回句柄（前四项必填，后四项为可选增强钩子）：
    return {
      group: arena,                                   // 地图根节点（挂到 scene）
      setRelicVisible: on => {...},                   // 遗物显隐
      setSelectShadow: (i,x,z,w,h) => {...},          // 选角接触阴影落位
      setSelectShadowsVisible: on => {...},           // 整组阴影显隐

      // ——可选：动态环境（天气等）——
      update: (T, dt, reduced) => {...},              // 每帧；主体只转发时间/降效标志
      setWeather: (name, mudState) => {...},          // 切天气/泥潭态（供演示与自动化）
      weatherInfo: () => ({weather, name, mud}),      // 读当前天气状态
      weatherNames: () => ['clear','wind','rain','mist'],
    };
  },
});
```

### 可选钩子为什么这样设计

主体**不认识天气**。它只在渲染循环里做一次通用转发：

```js
if (stageHandle.update) stageHandle.update(T, dt, reduced);
```

没有提供 `update` 的地图（如 V6 原版、晶格 Demo）行为完全不变；提供 `update` 的地图（天气版）据此驱动云层旋转、雨线、涟漪。这是「地图新增动态系统时主体零改动」的关键。

### 主体侧的稳定调用（不需要为换图改动）

| 调用 | 作用 |
|---|---|
| `arena.floorY` | 台面高度，落地基准 |
| `arena.anchor(name)` | 取落点 `{x, y, z}`（`y = floorY + 脚底抬升`） |
| `arena.view(name, ctx)` | 取机位 `{pos, look, fov}`；`ctx` 传 `{mobile,h,w}` |
| `arena.build(scene)` | 构建整张地图，返回句柄 |
| `stageHandle.set*()` | 遗物 / 接触阴影显隐与落位 |
| `stageHandle.update()` | 可选：每帧动态环境钩子 |

## 新增地图三步

1. 在 `stage-adapter.js` 里 `BAStage.define({...})` 一个新对象，按契约填齐字段；参照 `v6-floating-ruins`（默认）、`demo-crystal-arena`（换图验证）或 `map006-weather`（天气版）。
2. 打开原型时带参数 `?stage=<你填的id>`，即可用新地图跑完整入口。
3. 回归：`node scripts/verify-stage-adapter.mjs`（换图/机位）、`node scripts/verify-weather-stage.mjs`（天气四态/泥潭/回归，脚本在独立工作区）。

## MAP-006 天气版：新增动态系统如何复用接口

线上 MAP-006 在悬浮遗迹上加了天气系统（`client/src/battle3d/ruins-weather.ts`），但**几何/布局/机位常量（TABLE）没变**、台面高度仍 1.22。这是「同一张地图叠加动态系统」的典型场景——正确做法是复用几何、只加动态层，而不是重做一张地图。

`map006-weather` 适配器的做法：

1. **复用几何**：`build()` 内直接调用 `v6-floating-ruins` 的 build，得到完全一致的石台/栈桥/灯光/散景。
2. **叠加天气工厂** `makeRuinsWeather()`：复刻线上四态天气的可视契约——云海初霁 / 穿岛阵风 / 斜风骤雨 / 雨后薄雾，含岛底流云（InstancedMesh）、斜雨气流线（LineSegments）、雾色与雾距联动、泥潭预警（青蓝）与封路（橙棕）两态。
3. **通过可选钩子下发**：`update`（每帧动画）、`setWeather`（演示/自动化切天气）、`weatherInfo`/`weatherNames`（读状态）。主体零改动。

线上契约对应关系（供研发移植核对）：

| 原型内 | 线上 `ruins-weather.ts` | 说明 |
|---|---|---|
| `makeRuinsWeather().sync(w, mud, fog)` | `createRuinsWeather().sync(conditions, anchor, radius)` | 切天气 + 泥潭位置/状态 + 雾 |
| `makeRuinsWeather().update(T,dt,reduced)` | `createRuinsWeather().update(time, animate)` | 云转/雨线/涟漪，`reduced` 对应线上精简特效 |
| `WEATHER` 四态表 | `CLOUD_COLORS` / `RUINS_WEATHER_NAME` | 天气枚举与中文名 |
| 泥潭 `warn`/`active` | `mud.active` | 积水预警 → 泥潭封路 |

> 原型内是独立自洽实现（不依赖共享仓库模块），用于接口验证与视觉评审；线上以 `ruins-weather.ts` 为准。

天气态验收：`screenshots/map006-weather-weather-{clear,wind,rain,mist}.png`、`map006-weather-weather-mud-{warn,active}.png`。

## 迁移注意点

- **脚底抬升是通用视觉常量**（`FOOT_LIFT=0.03`），由适配层 `anchor()` 统一加到 `y`；新地图不要在主体里另写 `floorY+0.03`。
- **动态机位**（menu/select）是函数：menu 按横竖屏，select 还要按角色体型 `h/w` 调整距离和视点。
- **接触阴影**必须挂在地图根节点上并返回句柄，否则选角阶段的脚底接触点会丢失。
- **Demo 数据不随地图走**：席位名字、角色、准备态是模拟数据，留在原型主体；只有坐标从 `anchor()` 取。
- **灯光/雾也归地图管**：天气版通过 `sync()` 改雾色/雾距，主体不再碰。
- **动态系统走可选钩子**：新增粒子/天气/昼夜时，用 `update` 下发，别往主体塞地图分支。
