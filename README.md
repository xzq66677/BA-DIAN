# 拔典（BA DIAN）· 多人房间制生存游戏

基于石头剪刀布的回合制多人生存游戏。

> 代码仓库：https://github.com/xzq66677/BA-DIAN每回合所有存活玩家隐藏出拳判定行动资格，胜者再判定行动顺序，依次执行移动/攻击/回复（角色技能可改变规则），最后一名存活玩家获胜。

支持：真人联机（Socket.IO 房间制，**每房最多 10 人**）、单设备多人（隐私出拳）、**二次判定亲自出拳**（资格者逐子轮隐藏出拳决定行动顺序）、AI 玩家（休闲/普通/硬核三档难度）、10 个角色（9 个首轮验证角色 + 老大爷）、**3D 战场**（Three.js 低模人形 + 六棱石台房间，WebGL 不可用自动回退 2D 牌桌）、局内战绩统计、丢番茄小互动、横屏/竖屏自适应、机制测试场。

## 环境要求

- Node.js ≥ 20（开发验证使用 v24.21.0）
- npm ≥ 10

## 本地运行

```bash
# 1. 安装依赖
npm install

# 2. 全量自动化测试（645 用例，需 Node ≥ 22.15；见下方「测试」）
npm test

# 3. 构建（服务端 tsc + 客户端 vite）
npm run build

# 4. 启动（生产模式：服务端 + 静态客户端）
npm start
# → http://localhost:3100（端口可用环境变量 PORT 覆盖）
# 本机已配置 systemd 服务（开机自启/崩溃重启）：
#   sudo systemctl restart badian && journalctl -u badian -f

# 本机多种访问方式（本服务器实机部署时）：
#   直连:       http://<服务器IP>:3100（需云防火墙放行）
#   nginx路径:  http://<服务器IP>:11937/badian/（NSG已放行，手机直连可用）
```

### 入口模式

- **默认（电影感入口）**：未登录访问根路径先进入 V5.0 四段入口（开场 → 主菜单 → 作战室 → 选角 → 战场交接），实时 3D 低模角色；选角「确认出战」后弹出**房间设置**面板（昵称必填并记忆、本机玩家数、AI 数量、天气），再以所选角色创建/加入真实房间进入对局。
  - `?stage=<id>`：切换入口地图（`v6-floating-ruins` / `demo-crystal-arena` / `map006-weather`）。
  - 加入房间：在主菜单点「加入房间」，输入邀请码后走同样流程；加入时只填**自己**的昵称，本机只持有自己那一个身份。
  - 昵称必填：未设置过会自动生成带随机后缀的默认名（如 `棋手4821`），避免所有游客都叫同一个名字。
- **经典入口**：URL 加 `?entrance=classic`，或点入口页右上角「经典入口」，回到原卡桌首页（下方说明）。
- **原型探索**：`?proto=A|B|C` 为同一真实引擎对局的三种视觉架构原型，不受入口模式影响。

打开经典入口 `http://localhost:3100/?entrance=classic`（TCG 卡桌风格界面：深色卡桌 + 游戏王风角色卡 + 技能卡行动坞）：

- **大厅**：房间列表实时刷新、点击加入；角色卡池展示墙（点击看卡面与台词；无立绘角色显示占位卡）
- **AI 选角**：房主添加 AI 时可指定角色或随机（默认随机）；房主可随时更改已加入 AI 的角色
- **AI 难度**：房主在卡位区切换「休闲 / 普通 / 硬核」，本局所有 AI 统一生效（详见下文）；非房主看到当前难度的只读标签
- **3D 战场（默认）**：悬浮遗迹竞技场由六棱石台、程序化图腾、石桥和中央仪式台组成。房间按服务器 ID 固定，角色移动、攻击、回复、范围预警与延迟爆炸同步播放。可以拖动视角、滚轮缩放、恢复全局，或在「画面」切换自动镜头和精简特效。战场保留点击选房、目标高亮和 2D 切换。详见 [地图设计](docs/MAP_DESIGN.md)、[地图架构](docs/MAP_ARCHITECTURE.md)、[验收记录](docs/MAP_ACCEPTANCE.md) 和下方 [V6.0 地图任务进展](#v60--地图悬浮遗迹--map-任务进展)。
- **二次判定（行动排序）**：初次判定分出胜负后，若资格者 ≥2 人则进入排序判定——**资格者亲自出拳**（隐藏提交、逐子轮），每轮输者整组先动、赢者整组靠后，同侧继续递归；平局（同拳/三人循环）同组重出拳、不消耗回合；**领域不参与排序**、**不写角色判定历史**（大屁孩的暴走/自爆与排序无关）；AI 即时代出，房间内 ≥2 名真人时 30s 超时代掷；仅 1 名资格者时跳过排序直接行动
- **对局内（2D 牌桌 / 3D 不可用回退）**：斗地主式牌桌布局（上方对手座位条 / 中央牌桌与出拳揭示台 / 底部我的席位与手牌 / 右侧战斗日志）；WebGL 上下文丢失时自动无感回退 2D，对局不中断；**出拳揭示**——每轮判定结算后所有人可见彼此的石头剪刀布（提交期间保密封锁，公平不破坏）；**战斗演出**——受击斩击（弹出+斜向斩击+冲击闪光+伤害飘字+HP条平滑下降）、回复柔光、移动飞行动画（卡片跨房间 FLIP）、淘汰印章/复活爆发、AOE 房间告警、**大伊万完整演出链**（投掷物从投掷者卡面飞向目标房间 → 落点冲击波 → 房间内成员逐个结算；爆炸前目标房间持续显示「💣 预计第 N 回合末爆炸（平局顺延）」待爆警示），全部由服务端结构化事件经演出队列驱动（不快照差分猜测）；演出可 1×/2×/4× 倍速、跳过本段、全部跳过；局内发言（底部常驻面板，实时同步，可收起）、房主可踢人（点卡牌详情里的踢出按钮，对局中被踢=淘汰）
- **生命与角色状态**：2D 角色卡和 3D 名牌血条均显示当前/最大生命数值；点击血条打开只读状态详情，展示存活、躲藏、隐身、领域、复活次数、瞄准与已生效的角色公开状态。详情不包含未揭示出拳或判定历史；目前引擎尚无通用燃烧/中毒等持续负面状态，因此不会显示虚构状态
- **终局演出**：胜负判定弹层——胜者聚光+一次性金色光屑+结果摘要（终局回合/出局人数）；平局使用独立冷灰构图；关闭弹层后战场进入终局态（胜者卡金色光环+👑、空房间弱化），横幅显示完整结果；可随时「查看战场」跳过；房主点「🔄 再来一局」**直接以原座位开新局**（无需回大厅再点开始）
- **全局播报与反馈**：**每个公开动作都进全局播报**——战场中央横幅（图标 + 文本 + 服务端 `HH:MM:SS` + 停留秒数）+ 顶栏「📣 播报」抽屉（时间倒序、⭐ 重点过滤、未读徽标），不再需要翻日志找「刚才谁干了什么」；重大事件（淘汰/致命/领域/复活/终局）优先且拥堵时不被丢弃，阶段提示类只进抽屉不抢镜头（详见[全局播报](#全局播报每个动作都可见--反馈时间)）；运势全局仅一次、用后技能卡自动灰化；点击不可选目标（隐身/躲藏/异房间近战/远程未瞄准）时明确提示原因；打击感三件套——受击挤压脉冲、致命/重击微慢动作、白闪→红闪两段 + 沿攻击方向的击退；战斗日志抽屉收起时顶栏显示未读徽标

- **局内战绩**：顶栏「📊 战绩」打开统计面板，逐人显示出拳胜/负/平、造成与承受伤害、击杀数、行动次数、回复次数、移动次数、存活回合、被番茄砸中次数
- **丢番茄**：点座位上的 🍅（或卡牌详情里的 🍅/🥚/🌹）向任意存活玩家投掷，全房间可见飞行与命中动画，对方座位累计被砸次数；纯娱乐，**不进战斗日志、不改血量、不影响判定**，同一玩家 2.2 秒冷却
- **对局回放（已完成，暂未启用）**：录制与播放器已实现（状态帧去重、逐帧播放、0.5–4× 倍速、导出 JSON），但按 2026-11-20 要求**暂不发布、界面不挂入口**（`Game.tsx` 内 `REPLAY_ENABLED = false`，置 true 即恢复）；服务端录制逻辑保持不变，历史数据不受影响
- **`prefers-reduced-motion`**：系统开启「减少动态效果」时，演出自动降级为最短时长、无震动/闪烁的轻反馈；终局弹层光效/光屑静止、投掷物飞行隐藏，信息保持完整
- **屏幕适配**：手机横放（≤560px 高）自动切换紧凑牌桌——座位条压缩、中央分栏、手牌横向可滑、日志与发言改为可收起抽屉；手机竖屏隐藏侧栏并把牌桌改为内部滚动，保证「开始出拳」按钮始终一屏可见；桌面端整桌单屏不滚动
- **房间管理**：**每房最多 10 人**（本机玩家 + AI 合计，创建/加入/加 AI 三条路径服务端统一校验，入口下拉框联动收紧并显示「共 N/10 人」）；房主可解散房间（全员退出）；玩家可随时退出房间——**整台设备退出**（单设备多人的全部身份一起移除，对局中=引擎内淘汰公示），退出后房间无真人可继续（空/只剩 AI）则**默认解散**，仍有其他真人则对局继续；同一设备不能重复加入同一房间（不会出现两个自己）；首页被旧房间占用时提供「回到房间 / 退出旧房间」一键解除；胜负判定为全屏弹层（胜者卡面+再来一局）；昵称必填且本设备记忆

- **单人开局**：填昵称 + AI 数量 → 直接开局
- **创建房间**：获得 4 位邀请码 → 朋友在「加入房间」输入码加入 → 房主开始游戏
- **单设备多人**：「本机玩家数」选 2 以上 → 出拳阶段按提示传递设备，每人亲自出拳（提交后不回显拳种）
- **机制测试场**：首页入口，运行全部测试用例（PASS/FAIL、种子复现、完整结算日志）

## AI 难度

房主在大厅卡位区选择，整局统一生效。AI 与真人走**完全相同的引擎接口**（`submitThrow` / `submitAction`），不存在偷看隐藏出拳或直接改状态的作弊路径——难度差异只体现在「出拳策略」与「行动优先级」上。

| 难度 | 出拳策略 | 行动策略 |
|---|---|---|
| 🤖 休闲 | 纯随机 | 能打就打，否则随机移动；不会用技能组合 |
| 🤖 普通 | 上一轮对手的出拳做简单反制（出能赢它的拳），掺随机 | 优先击杀残血目标、残血自己优先回复、远程角色优先异房间目标 |
| 🤖 硬核 | 统计全场**已结算**出拳的频率分布，出最可能反制的手势（30% 概率扰动，避免被读死） | 威胁值排序（血量/攻击力/是否可秒）选目标，优先补刀收人头，技能与站位都按收益最大化 |

关键约束：AI 只在 `roundEnd` 之后、或自己出手时读取**已经结算并公开**的判定历史，因此难度提升不破坏隐藏出拳的公平性。所有随机数取自 `shared/src/rng.ts` 的座位随机流，固定种子下 AI 行为完全可复现（回放/测试同源）。

**对躲藏目标的「找出来」（Issue #61）**：同房间只剩躲藏者时，三档 AI 都会优先 `seek` 把目标找出来（普通按残血、硬核按威胁值排序），而不是空过或盲目移动；候选链兜底也含 `seek`，休闲档随机首选被拒时仍能落地。规则关闭 `allowSeek`、目标隐身（seek 无法解除）、异房间或已淘汰时不产生 `seek`；无视躲藏（拔棍）、AOE/辱骂接管攻击、纯远程与零攻击角色不浪费找出来——硬核伍六七/大剑客可直接打躲藏者，五条悟普通难度不再盲打躲藏目标。判定逻辑集中在 `server/src/ai.ts` 的 `seekTargets` / `shouldSeekHidden`，角色特化走 `aiStrategy` 钩子。

## 局外功能对规则的影响

战绩、丢番茄互动（以及暂未启用的回放）均为**只读观察层**，不进入判定：

- 战绩字段由引擎在结算时累计（`PlayerStats`），只做展示，不参与任何伤害/胜负计算
- 互动事件只走广播通道，不写 `game.logs`、不改 hp、不占行动次数
- 回放（暂未启用）是「状态帧录制」——服务端在状态签名变化时记一帧（每局上限 1500 帧、每房间保留最近 5 局），播放端只渲染帧，不回放隐藏出拳（`reveal` 字段始终来自已结算记录）

## 操作与超时

- **自身技能不需要选目标**：`targetHint: 'none'` 的技能（领域展开 / 抽取今日运势 / 领域强化 / 拔棍开关）选中后，确认条只剩「已选【技能】· 确认发动 · 取消」，不再要求点战场高亮卡牌，「确认发动」也不会因为没有目标而置灰。只有指向性技能（攻击 / 瞄准 / 找出来 / 五连鞭 / 投掷大伊万）才需要选目标或房间。
- **超时只在「有人等」时生效**：出拳 30s 代掷、行动 45s 跳过（可配置），但**仅当房间内有 ≥2 名真人**才布防。单人 vs AI 没有超时这回事——AI 是即时应答的，没有任何人在等你，你的回合不会被系统代掷或自动跳过；单设备多人（同一块屏幕）同样不布防。
- **AI 永不卡局**：AI 决策本身走「候选行动链」（非法就换下一个，最差 `skip`）；房间另有 1.2s 的 AI 看门狗，只要还停在该 AI 出拳/行动，就补驱动一次——它只驱动 AI、绝不替真人操作，因此取消超时也不会让对局僵死。
- **同一房间连打多局**：重开时战斗日志清空重来（服务端下发 `gameNo`，客户端据此清空），日志序号 `seq` 整个房间内单调递增（不随每局归零），因此第二局之后增量推送与去重都正常，不会出现「第二局日志不再更新」。

## 全局播报（每个动作都可见 + 反馈时间）

> Issue #39 / TASKS.md `T-6.0.1`：不用再翻日志找「刚才谁干了什么」。

一条链路：**引擎日志 → `shared/src/announce.ts` 规则表 → `AnnounceItem` → 服务端一次广播（所有座位同一份）→ 战场横幅 + 「📣 播报」抽屉**。

- **每个动作都可见**：攻击 / 技能 / 瞄准 / 躲藏 / 找出来 / 跳过 / 移动 / 回复 / 喝牛奶 / 今日运势 / 淘汰 / 复活 / 领域 / 大伊万 / 判定 / 行动顺序 / 回合小结 / 终局全部有播报；未知的新日志类型由 `fallback` 兜底——不存在「引擎写了日志但没人看见」。
- **有反馈时间**：每条播报带 `ts`（服务端生成时刻）与 `ttlMs`（横幅停留时长）。横幅显示 `HH:MM:SS`（房间时间线）并在右侧标注停留秒数；抽屉每行是「时间 · 图标 · 文本 · 停留时长」，可切「⭐ 重点」只看战斗/淘汰类。
- **重要信息 vs 次要信息（V2）**：**移动 / 攻击 / 技能 / 回血 / 躲藏**是重要信息（`priority: high`，横幅必播、拥堵保留、时长上调）；**胜负 / 回合 / 阶段 / 顺序 / 未命中**是次要信息（`priority: low`，只进抽屉、时长缩短）；淘汰 / 领域 / 复活 / 致命仍是最高规格的重大瞬间。详见下方[信息分级与时长](#信息分级与时长v2)。
- **不同类型的视觉表现不同**：每条播报带 `kind` 字段（8 类），横幅与抽屉按类型给出不同的形状、配色与动效——攻击=红色尖角+红光、技能=紫色斜角+光晕、回血=绿色胶囊、移动=蓝色虚线+滑入、躲藏=灰色虚线半透明、战果=金色双线、回合=小号灰条；横幅左侧还有「战斗 / 技能 / 回复 …」类型短标签。
- **文案精简**：`ANNOUNCE_MAX_TEXT` 从 64 收紧到 48，结构化规则用短句（如 `张三 R1→R2`、`李四 +1 HP（2→3）`、`张三 淘汰 李四`、`张三 获胜`），完整内容仍在战斗日志里可追溯。
- **优先级不抢镜头**：积压时保留队首与 `high`，其余过时的中低价值条目直接丢弃（`condenseAnnounceQueue`），避免播到过时消息。
- **零规则侵入**：播报只读 `LogEntry` 的 `type/text/data/important`，不改数值、不改结算顺序，也不影响隐藏出拳（提交阶段的日志里没有拳种）。所以「所有人可见」不会变成「提前泄露」。

### 信息分级与时长（V2）

| 信息类型 | `kind` | 优先级 | 停留时长 | 表现 |
|---|---|---|---|---|
| 移动 / 技能 / 回血 / 躲藏 | `move` / `skill` / `heal` / `hide` | `high` | `action` 1900ms | 各自独立配色与形状 |
| 攻击宣告 / 命中 / 伤害 | `attack` | `high`（未命中 `low`） | `combat` 2200ms（宣告 1900ms） | 红色尖角 + 红光 |
| 淘汰 / 领域 / 复活 / 致命 | `outcome` / `skill` | `high` | `major` 2600ms | 金色双线 / 危险红 |
| 胜负 / 回合 / 阶段 / 顺序 | `outcome` / `round` | `low` | `brief` 800ms | 小号灰条，只进抽屉 |
| 系统 / 错误 / 兜底 | `system` | 视重要性 | `brief` 或 `major` | 中性蓝灰 |

`ANNOUNCE_TTL` 常量：`brief 800` / `action 1900` / `combat 2200` / `major 2600` / `spotlight 2100`（毫秒）。`ANNOUNCE_VERSION = 2`。

### 扩展点（以后新事件怎么加）

引擎只要写了日志，新动作**默认就会出现在播报里**（兜底规则）。要定制图标/优先级/文案时，注册一条规则即可，服务端与客户端都不用改：

```ts
import { registerAnnounceRule } from './shared/src/announce.js';

const off = registerAnnounceRule({
  id: 'my-skill',
  summary: '我的新技能',
  match: (log, nameOf) => (log.data?.mySkill === true
    ? { icon: '🔥', text: `${nameOf(String(log.data.pid))} 点燃了战场`, tone: 'danger', kind: 'skill', priority: 'high', ttlMs: 3000 }
    : null),
}, { before: 'fallback' });   // 默认插在规则表最前；before 可指定插入位置
// 返回撤销函数：测试 / 热重载用完即撤
```

| 接口 | 说明 |
|---|---|
| `AnnounceItem.ts` / `ttlMs` | 服务端时刻与建议展示时长（即「反馈时间」） |
| `AnnounceItem.priority` | `high` / `normal` / `low`：决定是否上横幅、拥堵时是否保留 |
| `AnnounceItem.kind` | `move`/`attack`/`skill`/`heal`/`hide`/`outcome`/`round`/`system`：决定前端差异化表现形式 |
| `AnnounceItem.rule` | 命中的规则 id（埋点/定制渲染用；未知值按 `tone` 降级） |
| `buildAnnouncements(logs, { names, now })` | 纯函数：日志批次 → 播报项（幂等、保序、有界） |
| `mergeAnnouncements(prev, next)` | 客户端增量累积（seq 去重 + 截断） |
| `condenseAnnounceQueue(queue, incoming)` | 拥堵压缩：保留队首与 `high` |
| `simplifyAnnounceText(text)` / `clampAnnounceText(text)` | 精简日志原文（剥图标 + 短句替换）/ 截断到 48 字 |
| `fmtAnnounceClock(ts)` / `fmtAnnounceTtl(ms)` | `HH:MM:SS` / `0.8s` |

协议层：`room:update` 新增 `announces?: AnnounceItem[]`，与 `newLogs` 同批、所有座位完全一致；断线重连随 `catchUp` 补发最近 300 条日志对应的播报。旧客户端忽略该字段即可；旧服务端不发送时客户端按「无播报」安全降级。

## 战斗演出节奏（Pace）

> 反馈：AI 行动「太快、看不清」。演出时长原本散落在 `queue.ts` 与 `useBattlePresentation.ts` 十几处，调一次要改很多地方，所以抽成**档位表**。

一条链路：**引擎日志 → `parseBattleEvent` → `assembleClusters` 分簇 → `BattleEventQueue` 按档位时长逐条播 → 3D 特效/受击动画**。

- **四档可在运行时切换**：URL 加 `?pace=current` / `relaxed` / `cinematic` / `slow`（未知值回退默认）。默认档由 `DEFAULT_PACE` 一行决定，当前为 `slow`（慢速）。
- **座位组成策略（Issue #61）**：`resolvePresentationPace(seats, search)`（`client/src/battle/pace-policy.ts`）按房间座位计算档位——**真人/本机玩家 + AI 混合局强制 `slow`**，保证人机对局也看得清每一击；纯 AI / 纯真人局跟随 URL 或默认档。显式合法 `?pace=` 仍是最优先的调试覆盖。档位经 `QueueState.pace` 暴露到 `.battlefield` 的 `data-pace`，便于验收与调试。
- **所有数字集中在一处**：`PACE_PROFILES`（`client/src/battle/queue.ts`）——每种事件的基础时长、`fast` 压缩时长、簇间呼吸间隔、多段伤害/致命伤害停留、拥堵阈值，改档即可整体变快变慢，不用翻代码。
- **拥堵判定改看「条数」**：AI 由服务端 `kickAI()` 同步批量驱动，一次广播就带来**一整轮 AI 行动**（十几到几十条）。原先按「估算播放时长 > 9s」判积压，6~10 人局天然超标 → 每一批都被压成 `fast` 档 260ms/条，这才是「AI 太快」的根因。现在主判据是待播条数（`fastPendingEvents 60` / `turboPendingEvents 160`），正常回合按原速播，只有真正的洪水（重连补发、整局回放）才压缩。
- **演出预算对得上动画长度**：基线「一次攻击」= 行动 340 + 出手 200 + 伤害 640 = **1180ms**，而 3D 受击动画 `HIT_MS` 1250ms、出手 `FX_MS` 1400ms——动画还没播完就被下一条盖掉，观感自然偏急。各档把单次攻击拉到 1.18s / 1.71s / 2.18s / 2.71s，恢复「动作走完再下一条」。

| 档位 | `?pace=` | 缩放 | 单次攻击 | 18 条 AI 行动整段 | 适用 |
|---|---|---|---|---|---|
| 现有速度 | `current` | 1.00× | 1.18s | 8.8s | 原线上表现（对照基线） |
| 舒缓 | `relaxed` | 1.45× | 1.71s | 12.7s | 手机/普通对局，一眼看清「谁打谁、掉多少血」 |
| 从容 | `cinematic` | 1.85× | 2.18s | 16.2s | 大屏、旁观、直播 |
| **慢速（默认）** | `slow` | 2.30× | 2.71s | 20.2s | 逐帧讲解/复盘 |

API：

| 符号 | 用途 |
|---|---|
| `PACE_PROFILES` | 四档完整参数表（含 `base` / `fastMs` / `gapMs` / 阈值） |
| `DEFAULT_PACE` | 默认档位 id（改手感只改这一行） |
| `resolvePace(raw)` / `paceFromLocation()` | `?pace=` 解析（未知值安全回退） |
| `resolvePresentationPace(seats, search)` | 座位组成策略：人机混合局默认慢速，显式 `?pace=` 优先（`pace-policy.ts`） |
| `queue.setPace(profile)` | 局内即时切换（只影响后续事件） |
| `eventMs(e, mode, speed, reduced, pace)` | 单事件时长（导出供分析脚本/测试复用） |

节奏对照材料（同一场真实对局、四档各录一条 + 并排对比）见交付目录 `pace/`。

## 游戏流程

1. **初次判定（隐藏出拳）**：所有存活玩家同时出拳；服务端统一揭示判定。平局/三人循环算一个独立的平局回合（无人行动，回合末照常结算并翻页），下一回合重新判定；分出胜负时胜者（可多名）获得行动资格。
2. **二次判定（行动排序）**：资格者**亲自出拳**逐子轮判定排序，输者整组优先行动、赢者整组靠后；平局同组重出拳（不消耗回合）；**不剥夺任何人的行动资格**；领域与角色判定历史都不参与排序。
3. **行动阶段**：按队列依次执行一次行动 —— 移动（到任意玩家初始房间）/ 攻击（默认同房间近战1伤）/ 回复（回满血）+ 角色技能；躲藏/找出来为可选基础行动。
4. **回合末**：延迟事件结算（如大伊万爆炸，动态判定房间成员）；每回合输出「回合小结」重点摘要。
5. HP 归零立即淘汰；最后一名存活玩家获胜。
