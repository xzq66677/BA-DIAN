# 九步工作流

每步写出输入、可交付结果和失效条件。先确定谁可改共享文件，再拆单角色任务；同一核心文件同一时间只交给一名负责人。主 Agent 检查各步证据，不能用文档完成代替角色完成。

| 步骤 | 执行与输出 | 不通过时 |
|---|---|---|
| 1. 需求分析 | 核对角色 ID、能力、现有快照/日志、常用镜头、与旧角色同屏。填写 [Character Specification](templates/character-spec.md)：剪影信号、必需动作、非目标、基线和验收条件。 | 不清楚的机制回读引擎与测试；新增规则不属于视觉任务。 |
| 2. 资产准备 | 按[资产规范](CHARACTER_ASSET_SPEC.md)记录作者、输入、许可、格式、依赖、体积和三视图/姿态参考；先暂存并审查，最后决定能否入正式目录。 | 授权或格式不明时不入库，交主 Agent 处理；不得静默换来源。 |
| 3. 模型标准化 | 输出规范化源与可重现参数，检查 +Y、+Z、足底、身高、挂点、局部姿态及开销。工具自动检测轴向证据不足时，人工调整并保存前后对比。 | 回第 2/3 步改源；不在场景乃至规则层临时补偿角色模型问题。 |
| 4. 战场接入 | 继承既有容器、世界定位、房间泊位、朝向、镜头、名牌和生命周期，注册一个 `charId`。输出回退、实例复用及释放证据，见[集成规范](CHARACTER_INTEGRATION_SPEC.md)。 | 先恢复旧角色与 2D，再缩小集成改动。 |
| 5. 动画绑定 | 按能力选动作，区分原始资源、语义映射、控制器、触发、打断、完成和同步；登记每行的降级与验证方式，见[动画规范](ANIMATION_SPEC.md)。 | 缺动作可以用现有反馈降级；不能增加机制来展示动作。 |
| 6. 事件接入 | 从结构化日志到表现事件再到场景命令逐行核对，分别标记来源 PID/目标 PID/房间、时序、缺字段、快照收敛；使用[事件规范](EVENT_BINDING_SPEC.md)。 | 字段不足就降级或跳过；不得按文本、动画回调或 HP 差分猜击中。 |
| 7. 测试 | 在隔离目录进行类型、单元、集成、E2E 与画面采样，保留结果与失败现场；补测已有断言之外的状态竞争，见[测试规范](TESTING_SPEC.md)。 | 不删减断言；先证明问题和原因，再修、复跑并留档。 |
| 8. 视觉验收与迭代 | 用同尺度原帧、同 PID 和日志评审角色姿态、默认机位和窄屏构图。至少保存一次问题→修正→同条件复测。正常距离识别另用[视觉 QA](VISUAL_QA_SPEC.md)。 | 造型回第 3 步，UI/机位回第 4 步，动作可读性回第 5/6 步；无法人工或真机验收就保留缺口。 |
| 9. 交付归档 | 用[报告模板](templates/character-report.md)列双交付状态、改动、来源、证据、未通过项与下一步。用户未授权时不进入下一角色或阶段，不提交/推送/部署。 | 证据不能独立复核就补命令、样本键或路径；不把候选版称为已验证。 |

**可交给 Agent**：尺寸/命名/文件清单、姿态矩阵、单文件实现、专项测试、原始截图、日志对照与报告。**主 Agent 决定**：角色与范围、权利能否接受、路线上线门槛、共享接口、异常的修复边界、证据是否足够和是否结束迭代。人工辨识和真机结果只能由实际观察补齐。
