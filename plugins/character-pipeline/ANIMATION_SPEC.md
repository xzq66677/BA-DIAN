# 动画规范

| 层 | 当前落点 | 新角色交付要求 |
|---|---|---|
| 原始资源 | `gojo.ts` 的几何、局部关节、程序化姿态函数，不是 Clip/蒙皮 | 记录作者、文件、输入、默认姿态、可动结构；不同模型可以有不同关节。 |
| 语义映射 | `CharacterRig` 的 `idle`、`walk`、`attackSwing`、`flinch`、`dead`、`reviveRise` 等方法 | 列必需、可选和未支持动作及回退。不是每名角色都要有复活、领域或道具动画；兼容现有接口不等于新增角色能力。 |
| 控制器 | 场景持有姿态、局部进度、受击停顿、位移和镜头；rig 按参数更新局部关节 | 定义所用时间单位、周期/归一化进度及缺省姿态；测试同一进度的重复调用不累加偏移。 |
| 触发与同步 | 既有队列开窗，adapter 派命令；快照同步存活和房间 | 绑定实际命令和字段。使用动作采样点对齐既有视觉反馈，不以动作派发命中、回血、淘汰。 |
| 中断 | 实体移除/换角失效；死亡/起身不被迟到普通移动或攻击抢占；快照仍可换房 | 测 hit→death、death→revive、死亡晚到 move、旧补间、重开/卸载；不要假设跳过队列会清除已发往 Three 的效果。 |
| 完成 | 局部动作结束回到正确待机/走路/死态；倒地后淡出，复活恢复实例材质 | 复位关节、可见性和材质；结束回调只做本地清理，不能阻塞结算或依赖动画播完才更新权威状态。 |

**VERIFIED（gojo-v1）**：待机、出手、受击、起身、死亡有同 PID 实战帧。游走、施法等其他 rig 方法的姿态测试不是对应技能的实战证据。当前场景倒地约 0.55 秒、2.6 秒起淡出、3.4 秒隐藏，起身约 0.65 秒；这是该场景实现，不是规则时间。

**UNVERIFIED**：外部 Clip、`AnimationMixer`、动作重定向、待机混合与高倍速下的同步。以后先单模型验证 rest pose 和轴向，按角色维护映射，对缺 Clip 用原地姿态/原有反馈，测试恢复和监听解绑后再复用。不要让角色直接依赖引擎或调用服务器结算。
