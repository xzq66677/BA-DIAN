# 资产规范

## 入库前

1. 记录 `charId`（以共享角色配置为准）、版本化视觉 ID（如 `gojo-v1`）、作者/工具、源文件、全部参考输入、许可或内用限制。卡面可作造型参考；项目许可不是卡图或角色形象授权，也不提供分发可编辑资源的证明。
2. 暂存未经审查的生成/下载物，不直接放入运行目录。检查扩展名与格式、依赖、大小写、体积及实际来源；确认许可和项目预算之后才入库。程序化源使用 `client/src/battle3d/characters/<charId>.ts`；不要把截图、测试产物或编译目录作为源。
3. 优先读俯视剪影，其次读材质色块。用同屏旧角色比较站姿高度、动态轮廓和房间占用；预先记录预期的头/手/背锚点，缺少挂点时沿用场景既有回退，不强制伪造骨骼。

## 标准化与测量

- 局部 +Y 向上、+Z 正向，默认站姿脚底 y=0。场景封装仍负责台面、世界朝向与尺度；动作不携带跨房间根位移。记录缩放、站姿包围盒、头高和关键锚点，校验脚底不漂浮也不穿台。
- 程序化模型以现有 Three.js 为准：可用关节 Group 与 BufferGeometry；同关节的零件可合并，避免每帧新建几何/材质。记录网格、三角面、不同材质、几何数组字节数和包增量；同一角色不同 PID 若会独立闪色/淡出，不共享可变材质。没有适用于所有角色的五条悟硬阈值。
- 可执行检查：`git status --short` 确定实际入库清单；`git ls-files --others --exclude-standard client/src/battle3d/characters` 检查漏跟踪源；`wc -c client/src/battle3d/characters/gojo.ts` 记源文件字节；[专项测试](../../tests/ui/gojo-asset.test.ts) 检查高度、变换、实例隔离与旧资产回退。对外部文件另查 SHA-256、引用路径、纹理规格和源许可，这不能由单测代办。
- **人工处理路线**：对程序化模型检查中立姿态/三视角，修局部关节枢轴和几何偏移，再复测现场比例。对 DCC 模型（UNVERIFIED）先保留可编辑源，在 DCC 中校正变换、尺度、足底、原点和面数，修权重/挂点/贴图，烘焙原地动作后再导出；记录工具版本和导出设置，在实际战场复查材质与方向。

**VERIFIED（gojo-v1）**：同步运行时程序化生成，无外部模型、纹理、Clip 或加载依赖；项目内手写源和现有卡面引用可追溯。**UNVERIFIED（战场路线）**：GLB/glTF、外部骨骼、Mixer、资产联网/失败、异步替换、纹理共享与模型重定向。V5.0-A 只记录最小内存 GLB 与合成骨骼的冒烟；保留其预算作为试点候选，而非 V1.0 验收阈值。
